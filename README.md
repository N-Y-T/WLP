# SWP — Прогнозное планирование персонала (Workforce Lifecycle Planning)

Интерактивное приложение для стратегического планирования численности персонала
на всём жизненном цикле промышленного объекта. Один самодостаточный файл
[`index.html`](index.html) — чистый JavaScript + SVG, **без зависимостей и
без серверной части**, работает офлайн в любом современном браузере.

> Все расчёты — реальные, выполняются в браузере на введённых данных.
> Заглушек и фиктивных чисел нет: каждая цифра выводится из формул и параметров.

## Запуск

Откройте `index.html` в браузере (двойной клик) — приложение запустится сразу.
Состояние (виды работ, параметры, справочник, сценарии, допущения) автоматически
сохраняется в `localStorage` и восстанавливается при следующем открытии.

## Мультиязычный интерфейс (7 языков)

Переключатель языка — в шапке, рядом с кнопками «Руководство»/«Глоссарий».
Доступны: русский, English, қазақша, 中文, español, français, العربية (с
поддержкой RTL). Переводится весь интерфейс — вкладки, формы, таблицы,
подсказки, «Руководство» и «Глоссарий», а также сообщения ИИ-ассистента
(он отвечает на выбранном языке интерфейса). Выбор языка сохраняется в
`localStorage` отдельно от данных сценария.

## ИИ-ассистент (бесплатно — Google Gemini, опц. Claude)

В шапке — кнопка **«ИИ-ассистент»**. Это настоящий ИИ, встроенный прямо в страницу:
он сопровождает проект и **сам меняет данные**, вручную вводить ничего не нужно.
По умолчанию работает на бесплатном Google Gemini; можно переключить на Anthropic Claude.

Возможности:
- **Изучение ТЭО и документов** — прикрепите PDF/CSV/TXT (например, технико-экономическое
  обоснование), и ассистент извлечёт производственную программу, мощность, режим и фазы,
  затем спроектирует виды работ и параметры расчёта.
- **Реальное исследование** — при включённом веб-поиске ищет внешние данные (нормы труда,
  профстандарты/ЕТКС РК и РФ, дефицитность профессий, зарплаты, темпы автоматизации)
  и ссылается на источники; явно разделяет «из источника / экспертная оценка / посчитано системой».
- **Управление проектом через функции** — меняет вводные параметры, создаёт и правит
  виды работ, должности справочника, веса факторов риска и методологические допущения,
  сохраняет сценарии «что если», переключает вкладки. Каждое действие отражается в чате
  и мгновенно пересчитывает все вкладки.

**Подключение (бесплатно, без своего сервера):** в настройках панели (шестерёнка)
выберите провайдера и вставьте ключ. Ключ хранится **только в вашем браузере**
(localStorage, отдельно по провайдеру), запросы идут напрямую в API провайдера.

| Провайдер | Стоимость | Ключ | Модель по умолчанию |
|---|---|---|---|
| **Google Gemini** (по умолчанию) | **Бесплатный тариф** (карта не нужна) | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) | `gemini-2.5-flash` |
| Anthropic Claude | Платно (стартовые кредиты) | [console.anthropic.com](https://console.anthropic.com/settings/keys) | `claude-opus-4-8` |

По умолчанию используется **Google Gemini** — у него есть реальный бесплатный тариф,
бесплатный ключ и поддержка нужных возможностей: function calling (ассистент сам меняет
данные), загрузка PDF/ТЭО и веб-поиск Google Search. Если у выбранной модели веб-поиск
несовместим с инструментами, ассистент автоматически отвечает без поиска и предупреждает
об этом. Anthropic Claude остаётся как опция для тех, у кого есть ключ.

**Про лимиты бесплатного тарифа.** У бесплатного Gemini есть лимит запросов в минуту (RPM),
который сбрасывается каждую минуту (в аналитике Google виден только суточный расход, поэтому
кажется, что лимит ещё не достигнут). Ассистент делает **несколько** запросов на одно
сообщение (раунды вызова инструментов + поиск), поэтому минутный лимит выбивается быстрее.
При ошибке лимита (HTTP 429, «retry in N s») ассистент **сам ждёт указанное время и повторяет
запрос** — достаточно подождать. Если упираетесь часто, выберите модель **Gemini 2.5 Flash-Lite**
(больший лимит в минуту) или сделайте паузу.

## Руководство по каждому показателю

Кнопка **«Руководство»** в шапке открывает справку, где по **каждому** пункту расписано
**что это**, **зачем** и **как считается** (с формулами) — сгруппировано по разделам:
виды работ и нормирование, сводные показатели, жизненный цикл, прогноз и Монте-Карло,
анализ автоматизации, кадровые риски, CBA, план действий, сценарии, методология.
Дополнительно: кнопка **«Глоссарий»** (краткие термины), всплывающие подсказки «?» у полей
и вкладка **«Методология»** (все формулы и редактируемые допущения).

## Откуда берётся потребность: два источника

На вкладке **«Жизненный цикл»** есть переключатель **«Источник потребности»**:

| Режим | Что происходит |
|---|---|
| **Считать по нормам** (по умолчанию) | Потребность выводится из видов работ: явочная численность → сменность → резерв `k_сп` → множитель фазы → макро-сценарий. Вся цепочка видна в блоке **«Как получилась эта цифра»** на вкладке «Нормативный расчёт». |
| **План численности из документа** | Вы (или ИИ-ассистент по вашему ТЭО) задаёте численность **в людях** в четырёх точках каждой фазы. Формулы эти числа **не переопределяют**: нормы и кривая фазы не применяются, Q1–Q4 в «Детализации по должностям» и траектория строятся прямо по плану. |

Заполнять все четыре точки не нужно: достаточно начала и конца фазы — середины
система достраивает линейно и показывает серым курсивом (своё число их перебивает).
Фазы, для которых чисел не задано вовсе, считаются **нулём** — нормативная цифра
вместо них не подставляется, а незаполненные фазы перечислены в предупреждении под
таблицей. Если план пуст целиком, расчёт остаётся на нормах, и переключатель
прямо об этом сообщает.

### Детализация по должностям

Таблица показывает **одну фазу целиком**, а не весь проект сразу: фаза выбирается
чипами над таблицей (видны только фазы с ненулевой длительностью), а подписи Q1–Q4
несут месяц проекта — `Q1 · мес. 19`. Потребность фазы делится по группам, затем
между должностями внутри группы пропорционально колонке «Числ.» справочника;
**любую ячейку можно вписать вручную** —
значение сохраняется за этой должностью и этой фазой, «Итого» и «FTE цель»
пересчитываются по фактическим числам, а кнопка сбрасывает все ручные правки.

Ассистенту достаточно сказать «возьми численность по месяцам из документа» — он вызовет
функцию `set_phase_plan` и включит режим сам.

## Отраслевые шаблоны

Встроены три профиля (нефтегаз, машиностроение, IT/R&D), но список ими не ограничен:
в выпадающем списке есть **«+ Добавить свою отрасль»** — вводите название, и система
создаёт чистый профиль под ваши параметры. Ассистент умеет собрать его сам по документу
(инструмент `set_industry_template`): «сделай шаблон под горнодобычу по моему ТЭО».
Свои шаблоны сохраняются в `localStorage` и удаляются кнопкой рядом со списком.

## Многоработная система нормирования (§5)

Объём и нормы задаются **по каждому виду работ отдельно** (таблица на вкладке
«Нормативный расчёт»). Поддерживаются четыре методики из раздела 5 ТЗ:

| Методика | Формула явочной численности |
|---|---|
| По выработке | Чяв = Объём ÷ Норма выработки |
| По норме времени | Чяв = (Объём × Нвр) ÷ (Фсм × kвн) |
| По обслуживанию | Чяв = Число агрегатов ÷ Норма обслуживания |
| По рабочим местам | Чяв = Рабочие места × Коэфф. загрузки |

Списочная FTE работы = Чяв × Сменность × k_сп. Группа работы (core / aux / mgmt)
формирует оргструктуру. Итог по объекту = сумма по всем работам × множитель фазы
жизненного цикла. Добавляйте/удаляйте работы вручную или поручите ассистенту
(«разбей объём на виды работ по ТЭО»).

## Расчётные модели (ключевое)

- **Нормирование** — `computeBase()`: явочная/расчётная численность в FTE, сдвиг
  оргструктуры при автоматизации, распределение по должностям с кривой этапа Q1–Q4.
- **Монте-Карло** — `projectGap()`: детерминированный seed (воспроизводимость),
  случайные колебания оттока (±40 %), спроса (±5 %) и успешности найма; перцентили
  P10/P50/P90, вероятность дефицита, пиковый дефицит, первый месяц разрыва.
- **Анализ дожития** — `automationAnalysis()`: S(t)=exp(−λt), где hazard λ выводится
  из вектора навыков должности (рутинные операции → высокий риск; аналитика/ML → низкий).
- **Кадровый риск** — `riskAnalysis()`: 6 факторов нормируются в [0..1] и взвешенно
  сводятся в индекс 0–100; портфельный индекс взвешен по численности ролей.
- **CBA** — `cbaPair()`: найм `cbaHire` окладов, увольнение `cbaSever` окладов,
  обучение = база ДПО + недостающие навыки × ставка; ROI и чистая экономия.

### Цена обучения считается по навыкам, а не «за штуку»

У каждой должности есть своя ставка за навык, а у каждого навыка — **множитель
сложности** (вкладка «Методология», колонка «× цена»): 0.5 — короткий инструктаж,
1.0 — обычный курс, 2.5 — переподготовка с нуля. Поэтому «Машинное обучение» обходится
дороже «Обхода». Стоимость переобучения = база ДПО + Σ(недостающие навыки × их множители).

### Откуда взялся лексикон автоматизируемости

Это **стартовые оценки**, а не измеренный факт. Они собраны по открытым исследованиям
автоматизируемости профессий (методика Frey & Osborne «The Future of Employment», отчёты
McKinsey Global Institute, материалы ILO) и переложены с профессий на отдельные операции
по одному принципу: чем операция рутиннее, наблюдаемее и полнее описывается правилами,
тем выше её автоматизируемость. Числа редактируются на вкладке «Методология» и прямо
влияют на факторы «Навыки» и «Избыточность», а также на анализ дожития.

### Какая должность нужна на какой фазе

Потребность фазы делится **только между должностями, занятыми на этой фазе**. Матрица
«должность × фаза» — на вкладке «Нормативный расчёт»: отметки снимаются там, где роль
не нужна, и её доля уходит остальным. Без этого каждая должность получала долю в каждой
фазе, и на проектировании «работали» буровики и слесари. Демо-справочник поставляется
с осмысленными наборами (оператор — с ПНР, буровик — СМР и эксплуатация, аналитик
данных — проектирование и эксплуатация), чтобы поле было видно в работе. Ассистент
задаёт фазы через поле `phases` в `set_professions`.

Если по фазе не отмечена ни одна должность группы, потребность делится по всем —
иначе фаза молча потеряла бы людей.

### Сводка живёт в одном месте

Дашборд — единственная страница с крупными плитками; каждая ведёт ссылкой на вкладку,
где её число считается. На «Предиктивном анализе», «Кадровых рисках» и «Плане действий»
те же числа раньше повторялись крупными плитками — теперь это узкая строка сводки
со ссылкой «вся сводка — на дашборде», а место занимает то, что есть только на этой
вкладке.

### Одно правило распределения на всех вкладках

Потребность группы делится между её должностями **пропорционально колонке «Числ.»**
справочника — одинаково в нормативном расчёте, анализе автоматизации и кадровых рисках.
Раньше модуль автоматизации делил поровну, а модуль риска взвешивал по численности,
и один справочник значил разное на соседних вкладках. Если реальное соотношение иное,
впишите числа вручную в «Детализации по должностям».

Если виды работ покрывают не все группы (например, описан только основной процесс),
вспомогательная и инженерная группы получают 0%, а их должности — ноль людей во всех
модулях. Расчёт формально верен, но это редко то, что имелось в виду, поэтому такие
группы **называются прямо**, а доли можно переключить на ручные.

### Границы применимости

Вкладка «Методология» заканчивается разделом **«Чего эта модель не знает»**. Коротко:

- **Коридор P10–P90 — нижняя граница неопределённости, а не полная.** Он покрывает
  разброс оттока, успешности найма и заявленную неопределённость самого плана
  (параметр «Неопределённость плана потребности», по умолчанию 15%), но не аварии,
  остановку стройки или срыв поставок. Без этого параметра коридор считался бы только
  по помесячному шуму, который усредняется за горизонт, и выглядел бы обманчиво узким
  (±2% вместо реальных ±14%).
- **«Индекс вытеснения» — не вероятность.** Он выведен из экспертных оценок
  автоматизируемости, а не из наблюдённой частоты исчезновения профессий. Годится для
  сравнения ролей и проверки чувствительности к допущениям, не годится как «шанс в %».
- **Демографический риск** считается не по одному среднему возрасту, а как ожидаемая
  доля людей, достигающих пенсионного возраста за горизонт (нормальное распределение
  с редактируемым разбросом σ). Поэтому он зависит от длительности проекта и не
  обнуляется на среднем возрасте ниже пенсионного.
- **Зависимость от носителя компетенции** затухает гиперболически и никогда не
  обнуляется полностью: даже в группе из 500 человек уход ключевого носителя ощутим.

> Все «магические» коэффициенты (множители CBA, риск автоматизации по умолчанию,
> масштаб дожития) вынесены в явные параметры на вкладке **«Методология»** —
> их видно, можно править и можно поручить ассистенту подобрать по источникам.

## Зафиксированные допущения (требуют подтверждения заказчиком, §17 промпта)

1. **Юрисдикция / валюта** — Казахстан, расчёты в тенге (₸), пенсионный возраст 63 г.
   (параметр `PENSION_AGE` в коде).
2. **Отрасль** — преднастроен профиль нефтегазодобычи (есть шаблоны машиностроения и IT/R&D).
3. **Источник норм** — нормы и параметры вводятся пользователем / через CSV; утверждённой
   внешней библиотеки норм не предполагается.
4. **Горизонт / гранулярность** — помесячно, горизонт = сумме длительностей фаз.
5. **Данные рынка труда** — задаются экспертно полем `Рынок` (дефицитность 0..1) в справочнике.
6. **Хранение** — клиентское (`localStorage`) + экспорт/импорт JSON/CSV; интеграции
   с HRIS/ERP в этой автономной версии не подключены (закладываются контрактом импорта).

## Импорт / экспорт

- **JSON** — полный снимок состояния и справочника (кнопки «Выгрузить/Загрузить» на вкладках).
- **CSV** — справочник должностей (с BOM для корректного открытия в Excel).
- **PDF** — печать любой вкладки через системный диалог (адаптированные print-стили).
